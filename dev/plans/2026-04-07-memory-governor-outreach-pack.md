# Memory Governor Outreach Pack

## 1. GitHub / Blog Length

`memory-governor` is a community memory-governance layer for OpenClaw-style hosts.

It is not trying to replace Dreaming.
It is trying to complement Dreaming.

Dreaming is already good at background consolidation from short-term memory into long-term memory.
What still felt missing to me was a safer layer for:

- explicit corrections
- first-sighting emerging lessons
- routing discipline across multiple memory-writing skills
- manual hardening boundaries before something becomes durable truth

That is what `memory-governor` is trying to solve.

The core split looks like this:

- Dreaming:
  `daily_memory -> long_term_memory`
- `memory-governor`:
  correction staging, routing, target classes, manual hardening boundaries

The most important concept is `learning_candidates`:

- explicit corrections go there first
- emerging lessons go there first
- only later do they become `reusable_lessons`
- system-level rules still stay manual

I think the most upstreamable ideas are not the whole skill, but three specific concepts:

1. explicit correction staging
2. a clear Dreaming-vs-manual promotion authority split
3. treating `DREAMS.md` and `memory/.dreams/` as Dreaming artifacts, not target classes

## 2. GitHub / Discussion Medium

Built a community skill called `memory-governor` to complement OpenClaw Dreaming.

The idea is simple:

- Dreaming handles background consolidation
- `memory-governor` handles correction staging, routing, and hardening boundaries

The missing piece I kept feeling was explicit corrections:

- not important enough to harden immediately
- too important to just disappear into daily notes

So the skill adds `learning_candidates` as a low-commitment staging layer before something becomes a reusable lesson or system-level rule.

The part I think may actually be interesting upstream is not the whole skill, but:

1. explicit correction staging
2. Dreaming/manual promotion split
3. explicit `DREAMS.md` boundary guidance
